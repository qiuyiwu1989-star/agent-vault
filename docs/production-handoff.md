用户已要求升级 qiuyiwu.com/vault 生产环境。OpenDesign Docs MCP 延后，不阻塞上线。

## 代码状态

这是本地验证过的最小管理实现，不是可无鉴权直接上线的成品。代码包含 reader/admin、快照审阅/保全与历史兼容导入。17 项测试通过，浏览器实测新建 HTML → 草稿 → 本地发布成功。

## 部署前必须完成的适配

1. 读取实际站点仓库及部署规则，确认 DNS 对应生产服务器。已有资料要求走站点 GitHub Actions 部署，不手工覆盖全站，不 git clean。
2. 读取现有后台登录/会话校验方案。将 Vault 管理 API 接入相同鉴权、CSRF 与权限体系，再挂 /admin/vault/。当前 admin.py 在 GET 页面嵌入本机会话 token，只是本机隔离措施，不能当成公网登录认证，也不能仅通过改 Host 检查部署公网。
3. 替换代码中 127.0.0.1:8765/8766 的硬编码为配置化 public_base/admin_base。后台和用户 HTML 成果应保持不同安全来源或做严格隔离，不将任意 HTML 与后台同源执行。
4. 生产内容以服务器最新快照为准。不可用 10/04 包覆盖后来新增的内容。本地 72 项中的新增使用指南仅为本机说明，勿自动发布。
5. 原始 Markdown、数据库、历史和运维配置放 Web root 外。仅公开生成内容；保留 .md/.py/.sh 禁止访问规则和旧 URL 跳转。
6. 当前 managed 后台与早期 strict CLI 是不同写入链路；生产首版统一选定一个入口。与 OpenClaw 的 archive-vault.sh 协调，不能同时以各自全量目录覆盖网站索引。
7. 当前后台发布为本地重建，不是生产原子发布。部署版先构建完整临时输出并校验，再原子切换，保留上一版供恢复。

## 最小上线范围

保留现有 HTML 阅读页面与路径；增加统一搜索和分类入口；现有后台增加 Vault 列表、源码编辑、草稿保存、发布和历史恢复。高级字段治理、MCP、公开 GitHub 项目后续推进。

## 操作顺序与验收

- 备份最新 /vault、写入源、配置与数据库到非公网目录，记录校验值。
- 在隔离路径验证新版，确认基线数量、全部旧 URL、正文和附件，Markdown 与数据库不对公网开放。
- 先验证未登录管理 API 被拒绝，再用现有后台账号验证读写。
- 用一份明确测试成果验证草稿不公开、发布后可读、并发版本冲突、恢复历史。
- 协调旧 Agent 写入入口后切换，立即验证实际域名，并记录恢复操作。
