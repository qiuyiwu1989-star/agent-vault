# 输出契约 v1

2026-10-04。本版本面向新成果；不得批量改写历史正文来“通过校验”。

输入是 UTF-8 Markdown，文件名为 `YYYY-MM-DD-lowercase-slug.md`。日期为产出日，必须为有效日历日期并与元数据一致。首行唯一 H1，之后空行再接连续元数据：

```markdown
# 标题

- **日期**：2026-10-04
- **来源**：原文链接或明确的来源描述
- **作者**：作者或讲者
- **标签**：主题一 / 主题二
- **一句话**：不超过六十个字符的单行摘要

## 核心问题
正文。
```

通用必填字段为日期、来源、标签、一句话，非空且不得重复；标签 2–4 个、互不重复，使用 ` / ` 分隔。reading 要求作者或讲者；books 额外要求作者和类型。正文从 H2 开始，可有多个 H2 和更深标题，代码块内示例不计为正文 H1。

可选元数据不会被删除。来源描述可注明“仅书名，未经原书全文核验”；字段合法不代表来源真实。结构校验不能代替事实核查。

## 系统生成的记录

`schema_version=1`，稳定 UUID `id`，递增 `revision`，collection、filename、原始正文、归一化记录、SHA-256、actor、reason、UTC 创建时间。调用者不得通过改文件名绕过旧记录更新；更新既有 ID 时 collection 和 filename 不变。

当前四类 collection 保留原路径；html 的交互文件包支持另行实现。

## 状态

提交生成草稿修订。`published` 记录每份成果当前发布的修订，最新草稿可以领先于发布版本。发布显式指定当前修订，构建全部已发布成果的新快照，再切换活动版本。回滚恢复指定版本的发布清单，保留全部修订。

本地 CLI 的 actor 是责任记录，权限由可信执行环境控制；它不是认证系统。当前不存在“已审核”的机器标记，不得把 publish 成功称为内容已审核。

## 维护不变量

- 同一 collection/filename 的完全相同文本重试不增加修订。
- 不同文本必须匹配当前 revision；冲突后读取新版本再处理。
- 文档级内容提交不得用客户端目录重建远端全量目录。
- 发布目录只含已发布 HTML 与公开目录数据；源正文、草稿和历史留在私有存储。
- 同一份规范供校验、构建和 Skills 使用，Skill 不复制另一套字段定义。
