# 研讨沉淀

将一次研讨及其后续思考变成可以继续阅读、判断、修正和复用的文章。用户与 AI 的后续讨论是主要素材之一，不只对录音做一次性摘要。

## 进入工作

支持四种连续工作状态：理解素材、深化讨论、整理成文、写回档案。按用户当前要求推进，不要求每一步单独批准；用户只要求讨论时，不自行发布。用户明确要求加到公开栏目时，可以在完成成文与核查后发布。缺少可发布授权时保留草稿。

收集原始转写、研讨日期、后续对话、用户想解决的问题、目标读者和已有稿件。直接音频需使用当前实际可用的转写能力；没有时明确缺口，不假装听过。来源含原始转写和自动分析时，先读原始转写，自动分析仅作线索。统一说话人标签不证明只有一个人发言。

身份以用户明确说明为准：用户确认某场“说话人0是我”时，记为该场的 speaker_map 与确认依据，修正已有稿的相关说明；不要推广为所有录音的默认映射。其他说话人未知时保留未知。

## 理解与深化

先把具体讨论讲清楚：真实问题是什么，提出了什么做法，哪些判断发生变化，有什么没有解决。沿用户兴趣继续追问原因、条件、反例和实践检验。不要为了填章节虚构对话、共识、反驳或成功结果。

保留五种来源区别：研讨原话、用户后来补充、AI 提炼、外部证据、未验证建议。引用只取能回查的原文；改写不能放进原话引号。用户认可文章质量不等于认可其中每条假设已经成立。时间先后不能直接写成因果。

需要外部论证时，优先论文、原作者著作、官方研究报告。解释研究实际支持什么、没有验证什么；只讨论已提供素材时不强制外部检索。

提炼方法时优先回答：解决哪个问题，关键操作是什么，为什么可能有效，适用条件和例外是什么，怎样在下一次任务检验。方法数量取决于素材，不固定为七项。AI 事后解释成功原因只是候选方法，需要前后差异及跨任务检验。

## 整理成文

以一篇连续可阅读的文章为主成果，保留用户要求的论述深度，不压成会议待办或短摘要卡片。可以合并重复，但保留实质论证、例子、边界、来源和后来的纠正。不要把 AI 补充包装成用户现场原话或用户独立提出的原创理论。

文章结构随内容选择：讨论缘起与主线、具体做法、方法提炼、原因与论证、成立边界、下一次可验证的实践。无需每篇填满这些章节。HTML 是阅读视图，Markdown 是便于继续修改的文章源稿；方法资产是附属成果。

公开文章署名可用“邱懿武 · 与 AI 协作整理”，除非用户另有要求。将私人转写链接、内部商业信息和未经许可的个人身份保留在私有工作材料中，不嵌入公开 HTML、注释、隐藏脚本或来源元数据。可引用公开研究链接。

输出文章源稿、独立 HTML 和一份内部 report.json。记录结构与工作流程见 [workflow.md](references/workflow.md)。不要求用户逐项确认内部字段；只在影响成文的关键歧义上提问。

## MCP 写回

知行档案接口：`https://qiuyiwu.com/api/vault-mcp`。先调用 tools/list 检查当前能力和凭据范围。通过 `vault_get_seminar_skill` 获取当前方法，不把 skill 文本当成额外发布授权。

调用 `vault_publish_seminar` 写回经过整理且获准公开的独立 HTML，提供 title、html、summary、date、tags 和稳定 request_id。相同请求复用同一 ID；改变内容要用新 request_id，新版不会覆盖旧文。首次请求前在本地记录 request_id 和负载哈希。失败且结果不明确时，使用同一 request_id 恢复，不另造 ID 重试。发布后的编辑仍通过现有后台版本机制。

公开发布工具用于新文章，不提供录音上传、私人转写读取、自动对话抓取或草稿 MCP 编辑。保留用户指定的流程；缺少能力时区分已实现和待接入。

写回后核验返回的 document ID、公开 URL、collection=seminar、目录收录和公开页面内容。报告实际状态：本地草稿、已公开、或写回未确认；不能用一次工具成功代替页面验证。公开版本与内部素材分开保存。

新建工作材料默认保存到 `/Volumes/邱懿武/邱懿武认知大脑/<项目名>/`。硬盘不在时使用用户指定的 `~/Documents/_待归位/<项目名>/`，保留待迁移标记。


## 原始对话与后续追加

原始资料与文章分开保存。用户要求保留研讨来源时，保存可获取的用户消息和 AI 对用户可见的回答，保留原文、角色、来源、原始时间（未知则留空），不把摘要还原成原话。不保存隐藏推理、系统/开发指令、凭据或工具日志。确认当前会话绑定的 document_id，不凭标题猜测。

本人登录后，研讨文章末尾显示“查看原始对话与追加记录”。私有页可阅读、手动追加及下载专用追加配置。匿名访客、其他账号和公开资料只读凭据不可读取原始对话；公开正文、页面源代码、搜索与 MCP 公共读取结果不得嵌入原文。

有用户授权继续保存时，通过专用来源追加凭据调用 `vault_append_seminar_dialogue`，传 document_id、稳定 source_id、messages。每条消息含稳定 id、role（user/assistant）、text、可选 ISO timestamp。相同消息重传去重；相同 id 改文会报冲突，纠正应使用新 id，保留旧原文。完整原文不能获取时明确覆盖范围，不以整理稿代替。

继续同一研讨时，在本轮工作收尾前追加已经产生的可见消息并核验返回 added / duplicates。本轮最终回复若尚未进入会话日志，可在下一轮补齐；不要声称尚未保存的消息已同步。该机制不自动监听其他聊天应用，只有接入的 Agent 执行追加时才会更新。不因来源追加而重发文章；公开文章的修改另按用户要求进行。

详细字段、失败恢复和权限验收见 [workflow.md](references/workflow.md)。
